# 样例 / Example：content-data-review

> 来自团队真实情况：已发片登记表在复盘时**还没有任何后台数据**。这个样例展示的正是技能最重要的一条规则——没有数据就写「无数据」，不估算。
> Real situation: when the review ran, the published-video ledger had no backend data yet. This shows the core rule — no data means "无数据", never an estimate.

## 输入 / Input
「复盘一下上周发的那条『热水洗手更干净？』」
附件：已发片登记表（表头齐全，播放、完播等列为空）。

## 输出 / Output
| 指标 | 24h | 72h | 7d | 来源 | 抓取时间 |
|---|---|---|---|---|---|
| 播放 | 无数据 | 无数据 | 无数据 | — | — |
| 完播率 | 无数据 | 无数据 | 无数据 | — | — |
| 3 秒留存 | 无数据 | 无数据 | 无数据 | — | — |
| 涨粉 | 无数据 | 无数据 | 无数据 | — | — |

```
本周结论: 不下结论 —— 登记表中该条无任何后台数字。
缺数据: 请负责人提供创作者后台「作品分析」截图：
  播放、完播率、2s/3s/5s 跳出、平均播放时长、涨粉、互动（24h / 72h / 7d 各一张）
拿到后: 先对比本账号近 10 条中位数，再按 3s留存 → 完播 → 互动 → 涨粉 的顺序找第一个掉链子的环节。
```

**这个样例展示了什么**：复盘技能最常见的失败是「看起来合理」的编造数字。这里 agent 没有猜，而是列出缺口、给出具体的截图清单。
